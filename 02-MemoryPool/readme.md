# SGI-STL-MemoryPool

## 项目简介

本项目使用 **C++** 完整复刻实现 **SGI STL 经典双层空间配置器内存池**，严格遵循原生设计思想，实现一级大块内存分配器 + 二级小块内存池组合方案，完美适配 STL 容器作为自定义空间配置器使用，可用于学习底层内存管理、解决高频小块内存分配带来的性能损耗与内存碎片问题。

## 设计思想

1. 分层管理
   - 一级空间配置器：负责**128 字节以上大块内存**，直接封装系统`malloc/free/realloc`，专注实现内存耗尽 OOM 异常兜底机制
   - 二级空间配置器：负责**128 字节及以内小块内存**，采用**8 字节内存对齐**，划分 16 组自由链表管理空闲内存块
2. 核心优势
   - 减少系统调用：规避频繁调用`malloc/new`带来的性能开销
   - 消除内存碎片：通过内存池统一管理小块内存，避免服务器长期运行产生零散空闲内存无法使用的问题
   - 线程安全：内置互斥锁，支持多线程并发分配、回收内存
   - 灵活扩容：内存池不足时自动向系统申请内存，闲置碎片内存自动回收复用

## 核心架构说明

### 1. 基础规则常量

```c++
enum { _ALIGN = 8 };      // 内存对齐基数
enum { _MAX_BYTES = 128 };// 大小内存划分阈值
enum { _NFREELISTS = 16 };// 自由链表总数量
```

自由链表下标对应：0 号存放 8 字节内存块、1 号存放 16 字节，依次递增至 128 字节。

### 2. 自由链表节点设计

采用**共用体**实现零额外内存开销：空闲时作为链表节点串联内存块，分配后直接交由用户存储业务数据，仅用单字节字符数组标记内存首地址。

### 3. 核心全局变量

- 内存池边界指针：`_S_start_free`、`_S_end_free` 管控整块内存池范围
- 总内存统计：`_S_heap_size` 记录程序累计向系统申请的堆内存大小
- 自由链表数组：统一挂载不同规格空闲内存块
- 互斥锁：保障多线程操作内存池与自由链表安全

## 核心功能实现

### 1. 内存分配 allocate

1. 判断申请内存大小，区分调用一级 / 二级配置器
2. 小块内存通过位运算对齐，精准定位对应自由链表
3. 链表存在空闲内存：**头删**取出内存直接返回
4. 链表无空闲内存：调用填充函数，向内存池批量申请内存并串联链表

### 2. 内存释放 deallocate

1. 大块内存直接调用`free`释放
2. 小块内存通过**头插**方式，归还至对应规格自由链表，实现内存复用

### 3. 内存重分配 reallocate

支持内存动态扩容、缩容，自动判断内存类型：

- 超大块内存直接调用系统`realloc`
- 同规格对齐内存无需重新分配，直接复用原内存
- 规格不同则新分配内存、拷贝有效数据、释放旧内存

### 4. 对象构造与析构

遵循 STL 标准设计，**内存管理与对象生命周期分离**：

- `construct`：定位 new 原地构造对象，不分配新内存
- `destroy`：仅调用析构函数销毁对象，不释放底层内存

### 5. 内存池填充 & 系统内存申请

- 一次性默认批量申请 20 个同规格内存块，减少系统调用次数
- 内存池剩余零碎内存自动回收挂载自由链表
- 系统`malloc`申请失败时，自动挪用更大规格空闲内存兜底

### 6. OOM 内存耗尽处理

一级配置器内置**函数指针回调机制**，用户可自定义内存释放应急函数；内存分配失败时循环执行自救逻辑，无自定义回调则直接抛出`std::bad_alloc`异常。

## CMake 编译配置

### CMakeLists.txt 完整内容

```cmake
cmake_minimum_required(VERSION 2.8)
project(memory_pool)

# 配置编译标准、线程库支持
set(CMAKE_CXX_FLAGS "${CMAKE_CXX_FLAGS} -std=c++11 -pthread")
# 引入头文件搜索路径
include_directories(include)
# 批量读取src下所有源文件
file(GLOB SRC_FILES src/*.cpp)
# 生成可执行程序
add_executable(memory_pool ${SRC_FILES})
# 链接线程库，适配mutex多线程
target_link_libraries(memory_pool pthread)
```

## 关键知识点总结

1. **位运算对齐**：通过位运算快速向上规整内存至 8 的倍数，是内存池核心优化技巧
2. **volatile 二级指针**：禁止编译器优化缓存，保证多线程下自由链表数据实时性
3. **内存池分层逻辑**：二级负责高效复用，一级负责兜底容错，分工明确
4. **模板适配**：完美兼容所有 STL 容器，可直接替换`vector/list/map`默认空间配置器
5. **工业级设计思想**：当前主流服务器内存池、游戏服务端内存管理均借鉴此架构
