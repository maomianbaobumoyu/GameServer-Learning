面试可能经常会考到内存池，进程池，线程池，连接池。先来学习下内存池。

不管是C的malloc和free，还是C++的new和delete，在应用时遇到频繁的小块内存的分配和释放，可以对于应用程序在内存管理方面效率有影响，降低性能。所以使用内存池来对小块内存的开辟和释放，来提高性能。

SGI相当于第三方厂商封装的STL。

Allocator空间配置器

比如vector中使用,这个空间配置器是有默认实现的，实际用户使用时直接传入类型就行，vector<int>

```c++
Template<typename T,typename_Alloc=allocator<T>>

Class vector
```

Allocator主要包含四个核心功能，同时做了双层逻辑分离：

allocate：主要给容器开辟内存空间=>malloc

deallocate：主要给容器释放内存空间=>free

construct：负责给容器构建一个对象=>定位new实现

destory：负责析构对象=>直接调用对应的析构函数 p->~T()

核心设计分离：分离了对象的内存开辟和对象构造，分离了对象的析构和内存的释放

SGI_STL提供了两个Allocator的实现：

一级allocator空间配置器依然用的malloc和free

二级allocator空间配置器是基于一个内存池的实现。

在stl_vector中vector被定义为：

```c++
template <class _Tp, class _Alloc = __STL_DEFAULT_ALLOCATOR(_Tp) >

class vector : protected _Vector_base<_Tp, _Alloc>
```

push_back 源码：

```c++
void push_back() {
  if (_ M_finish != _M_end_of_storage) {
    construct(_M_finish);
    ++_M_finish;
  }
  else
    _M_insert_aux(end());
}
```

逻辑上应该是在容器底层内存去构造一个对象出来，在C++标准库中任何allocate,deallocate,construct,destory操作都是通过空间配置器做的（封装了这四种方法）。

在stl_vector的push_back中的_ M_finish就是最后一个元素的后继位置，在这个位置构造新元素后，_M_finsh再加加，并且使用它自己写的construct函数来构造。

无元素版本 construct：

```c++
template <class _T1>
inline void construct(_T1* __p) {
  _Construct(__p);
}
```

实际上construct是一个全局的函数模板，底层是定位new。

有元素版本 construct：

```c++
template <class _T1, class _T2>
inline void construct(_T1* __p, const _T2& __value) {
  _Construct(__p, __value);
}
```

带参 push_back 源码：

```c++
void push_back(const _Tp& __x) {
  if (_M_finish != _M_end_of_storage) {
    construct(_M_finish, __x);
    ++_M_finish;
  }
  else
    _M_insert_aux(end(), __x);
}
```

在这个指针p指向的内存上构造一个值为value的对象。

在pop_back中它也没有使用全局空间配置器，使用的也是自定义的全局函数模板。

pop_back 源码：

```c++
void pop_back() {
  --_M_finish;
  destroy(_M_finish);
}
```

destroy、_Destroy 源码：

```c++
template <class _Tp>
inline void destroy(_Tp* __pointer) {
  _Destroy(__pointer);
}

template <class _Tp>
inline void _Destroy(_Tp* __pointer) {
  __pointer->~_Tp();
}
```

调用指针，指针指向了要析构的对象，调用析构函数。

只是析构对象，不会释放容器内存，容器的内存可以之后放其他对象。所以把容器中不要的对象只用析构，不用delete。

SGI_STL中的容器：底层存储的对象的构造和析构是由定义的全局的函数模板Construct和Destory完成的。

Construct底层通过定位new实现，Destory底层通过调用对应析构函数实现。

STL容器中的空间配置器最终只剩下了allocate和deallocate功能，因为construct和destory逻辑已经抽离为全局函数。
