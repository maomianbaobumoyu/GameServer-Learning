### 阻塞IO

![image-20260525205345948](C:\Users\不二家sir\AppData\Roaming\Typora\typora-user-images\image-20260525205345948.png)

编程简单，当阻塞于read时，通过系统调用查看内核的TCP缓冲区中是否有数据，没有就一直等待，有就拷贝数据到用户空间的buf中，处理完后唤醒当前应用进程。

### 非阻塞IO

![image-20260525205733204](C:\Users\不二家sir\AppData\Roaming\Typora\typora-user-images\image-20260525205733204.png)

使用setsocketopt(sockfd)将fd设为非阻塞模式，调用read时，通过返回值判断读取状态。

### IO复用

![image-20260525205923696](C:\Users\不二家sir\AppData\Roaming\Typora\typora-user-images\image-20260525205923696.png)

通过将事件注册到select/poll/epoll中，阻塞检测事件发生，检查到事件就执行对应的回调函数。这里的IO复用默认是阻塞的，也可以设置timeout改为非阻塞。

在一个线程里通过IO复用监听接口，可以处理很多socket。

### 信号驱动

![image-20260525210659718](C:\Users\不二家sir\AppData\Roaming\Typora\typora-user-images\image-20260525210659718.png)

通过调用sigaction注册SIGIO的信号处理程序(回调操作)。

内核在第一个阶段是异步，在第二个阶段是同步；与非阻塞IO的区别是它提供了消息通知机制，不需要用户进程不断轮询检查，减少了系统API调用次数，提高了效率。

### 异步IO

![image-20260525211255824](C:\Users\不二家sir\AppData\Roaming\Typora\typora-user-images\image-20260525211255824.png)

这是异步非阻塞IO，Node.js采用的网络IO模型。整个过程不耗费应用进程的时间。

```c++
struct aiocb {
    int                     aio_fildes;
    off_t                   aio_offset;
    volatile void          *aio_buf;
    size_t                  aio_nbytes;
    int                     aio_reqprio;
    struct sigevent         aio_sigevent;
    int                     aio_lio_opcode;
};
```
