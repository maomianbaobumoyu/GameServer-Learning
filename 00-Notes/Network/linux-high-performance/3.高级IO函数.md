## fcntl函数

fcntl函数提供了对文件描述的各种控制操作。

```c++
#include<fcntl.h>
int fcntl(int fd,int cmd, ...);
```

fd参数是被操作的文件描述符，cmd参数指定执行何种类型的操作。根据操作类型的不同，该函数还可能需要第三个参数arg。

![image-20260530095917018](C:\Users\不二家sir\AppData\Roaming\Typora\typora-user-images\image-20260530095917018.png)

fcntl函数失败返回值如图片所示，失败返回-1并设置errno。

在网络编程中，fcntl函数经常用来将一个文件描述符设置为非阻塞的。

```c++
int setnonblocking( int fd )
{
    int old_option = fcntl( fd, F_GETFL );       /* 获取文件描述符旧的状态标志 */
    int new_option = old_option | O_NONBLOCK;   /* 设置非阻塞标志 */
    fcntl( fd, F_SETFL, new_option );
    return old_option;                          /* 返回文件描述符旧的状态标志，以便日后恢复该状态标志 */
                                               
}
```



## sendfile函数

sendfile 函数在两个文件描述符之间直接传递数据（完全在内核中操作），从而避免了内核缓冲区和用户缓冲区之间的数据拷贝，效率很高，这被称为零拷贝。

```c++
#include <sys/sendfile.h>
ssize_t sendfile(int out_fd, int in_fd, off_t* offset, size_t count );
```

in_fd 参数是待读出内容的文件描述符，out_fd 参数是待写入内容的文件描述符。offset 参数指定从读入文件流的哪个位置开始读，如果为空，则使用读入文件流默认的起始位置。count 参数指定在文件描述符 in_fd 和 out_fd 之间传输的字节数。sendfile 成功时返回传输的字节数，失败则返回 -1 并设置 errno。

该函数的 man 手册明确指出，in_fd 必须是一个支持类似 mmap 函数的文件描述符，即它必须指向真实的文件，不能是 socket 和管道；而 out_fd 则必须是一个 socket。由此可见，sendfile 几乎是专门为在网络上传输文件而设计的。

```c++
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>
#include <assert.h>
#include <stdio.h>
#include <unistd.h>
#include <stdlib.h>
#include <errno.h>
#include <string.h>
#include <sys/types.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <sys/sendfile.h>

int main( int argc, char* argv[] )
{
    if( argc <= 3 )
    {
        printf( "usage: %s ip_address port_number filename\n", basename( argv[0] ) );
        return 1;
    }
    const char* ip = argv[1];
    int port = atoi( argv[2] );
    const char* file_name = argv[3];

    int filefd = open( file_name, O_RDONLY );//只读打开文件
    assert( filefd > 0 );
    struct stat stat_buf;//获取打开文件的信息
    fstat( filefd, &stat_buf );

    struct sockaddr_in address;
    bzero( &address, sizeof( address ) );
    address.sin_family = AF_INET;
    inet_pton( AF_INET, ip, &address.sin_addr );
    address.sin_port = htons( port );

    int sock = socket( PF_INET, SOCK_STREAM, 0 );
    assert( sock >= 0 );

    int ret = bind( sock, ( struct sockaddr* )&address, sizeof( address ) );
    assert( ret != -1 );

    ret = listen( sock, 5 );
    assert( ret != -1 );

    struct sockaddr_in client;
    socklen_t client_addrlength = sizeof( client );
    int connfd = accept( sock, ( struct sockaddr* )&client, &client_addrlength );
    if ( connfd < 0 )
    {
        printf( "errno is: %d\n", errno );
    }
    else
    {       //sockfd,文件fd,默认起始位置，文件大小
            sendfile(connfd,filefd,NULL,stat_buf.st_size);
            close( connfd );
    }

    close( sock );
    return 0;
}
```

这里的struct stat用来获取文件的信息

```c++

struct stat {
    off_t     st_size;    /* 文件总大小（字节），sendfile 必须用！ */
    mode_t    st_mode;    /* 文件类型/权限（判断是不是普通文件） */
    time_t    st_mtime;   /* 最后修改时间 */
};c
```

## mmap/munmap 函数

核心是文件映射与共享内存，是零拷贝和进程间通信的关键技术

`mmap`：申请一段内存空间，支持两种核心模式：

1. **文件映射**：把磁盘文件直接映射到进程虚拟内存，操作内存就等于操作文件，省去`read/write`的用户态拷贝，是零拷贝场景的常用方案
2. **匿名映射 / 共享内存**：用于进程间通信的共享内存，或无文件关联的匿名内存分配

`munmap`：释放`mmap`创建的内存映射，回收系统资源

```c++
#include <sys/mman.h>
// 创建内存映射
void* mmap( void *start, size_t length, int prot, int flags, int fd, off_t offset );
// 释放内存映射
int munmap( void *start, size_t length );
```

##### `mmap` 参数详解

|   参数   |        含义        |                         常用设置                         |
| :------: | :----------------: | :------------------------------------------------------: |
| `start`  | 内存映射的起始地址 | 填`NULL`，让系统自动分配地址（最常用，避免手动分配冲突） |
| `length` |   映射的内存长度   |     映射文件时一般等于文件大小；匿名映射时按需求设置     |
|   `fd`   | 要映射的文件描述符 |    映射文件时填`open`返回的 fd；匿名映射时忽略该参数     |
| `offset` |  文件映射的偏移量  |    从文件的哪个位置开始映射，一般设为`0`（从头映射）     |

##### `prot`：内存段访问权限（保护模式）

控制映射内存的读写执行权限，可按位或组合：

- `PROT_READ`：内存段可读
- `PROT_WRITE`：内存段可写
- `PROT_EXEC`：内存段可执行
- `PROT_NONE`：无任何访问权限（几乎不用）

> 注意：权限不能超过文件本身的权限（比如文件只读，就不能设置`PROT_WRITE`）

##### `flags`：映射模式控制（核心）

控制内存修改后的行为，常用值如下，其中`MAP_SHARED`和`MAP_PRIVATE`是互斥的：

|      标志       |                           含义                           |             适用场景             |
| :-------------: | :------------------------------------------------------: | :------------------------------: |
|  `MAP_SHARED`   |  共享映射：内存修改会同步回磁盘文件，也可和其他进程共享  |     文件映射、进程间共享内存     |
|  `MAP_PRIVATE`  | 私有映射：内存修改是进程私有，不会同步到文件（写时复制） |    只读文件映射、私有内存分配    |
| `MAP_ANONYMOUS` | 匿名映射：不关联文件，内存初始化为 0，忽略`fd`和`offset` | 进程间匿名共享内存、临时内存分配 |
|   `MAP_FIXED`   |   强制映射到`start`指定的地址（不推荐，容易地址冲突）    |           特殊底层场景           |
|  `MAP_HUGETLB`  |              使用大内存页分配，减少页表开销              |         高性能大内存场景         |

------

##### 返回值与错误处理

- `mmap`：成功返回映射内存的起始地址；失败返回`MAP_FAILED`（即`(void*)-1`），并设置`errno`
- `munmap`：成功返回`0`；失败返回`-1`，并设置`errno`

> 补充：进程退出时所有映射会自动释放，但建议手动调用`munmap`，避免资源泄漏

------

##### 关键特性

1. 文件映射的零拷贝优势

   普通文件读写需要 read/write在内核缓冲区 ↔ 用户缓冲区之间拷贝数据；

   mmap 映射后，可直接在用户态操作内存，修改会由内核自动同步到文件，省去用户态拷贝，适合大文件读写、网络文件传输场景。

2. 进程间通信（IPC）

   多个进程映射同一个文件（使用MAP_SHARED），就能共享同一段内存，实现高效 IPC，性能比管道、消息队列更高。

3. 匿名映射的灵活使用

   配合 MAP_ANONYMOUS  \+  MAP_SHARED，可以创建父子进程共享的匿名内存，用于 fork 后的进程间通信。

------

##### 跟sendfile对比

- `sendfile`：内核态零拷贝，只能从文件到 socket 单向传输，简单高效
- `mmap`：用户态可操作的零拷贝，支持双向读写，灵活度更高，但需要手动管理同步（如用`msync`强制刷新到磁盘），适合需要修改文件的场景
