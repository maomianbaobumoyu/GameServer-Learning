# TinyWebServer
基于epoll+Reactor模型的轻量级高并发HTTP服务器，支持GET/POST请求，多线程异步处理业务。
本项目为C++网络编程入门实战，为后续游戏服务器开发打下基础。

## 技术栈
C++、Linux、epoll、Reactor、线程池、HTTP/1.1

## 核心功能
- ✅ 支持ET/LT两种epoll触发模式，可通过命令行动态切换
- ✅ 基于线程池的异步业务处理，充分利用多核CPU
- ✅ 主从状态机解析HTTP请求，支持GET/POST方法
- ✅ RAII管理socket文件描述符，避免资源泄漏
- ✅ 支持静态文件返回和POST请求回显
- ✅ 完整的异常处理和优雅退出机制

## 编译运行
```bash
# 创建编译目录
mkdir build && cd build

# 编译
cmake .. && make

# 运行服务器（参数：端口 线程数 模式(ET/LT)）
./http_server 8080 4 ET

# 测试GET请求
curl http://127.0.0.1:8080/index.html

# 测试POST请求
curl -X POST -d "name=test&age=18" http://127.0.0.1:8080
```

## 项目架构

```bash
客户端 → epoll事件循环 → 线程池 → HTTP解析 → 业务处理 → 响应客户端
```

## 性能测试与内存检测

### 1. 压测结果

**测试环境**：CentOS 7，2 核 4G 虚拟机

**测试命令**：`wrk -c 1000 -t 4 -d 30s --timeout 2s http://127.0.0.1:8080/index.html`

**测试结果**：

- 总请求数：1,024,784
- 平均 QPS：**34,053.71**
- 平均延迟：17.34ms
- 99% 延迟：1.63s
- 吞吐量：12.11MB/s
- 错误数：97（均为超时，无连接 / 读写错误）

## 项目亮点

1. **设计模式应用**：采用策略模式实现 ET/LT 模式动态切换，符合开闭原则
2. **高并发优化**：使用 EPOLLONESHOT 避免多线程下的事件竞争问题，1000 并发下 QPS 达 3.4 万
3. **内存安全**：RAII 管理所有资源，Valgrind 检测零内存泄漏
4. **代码规范**：头文件与源文件分离，模块化设计，易于扩展
5. **完整的工程化实践**：包含性能测试、内存检测、文档说明
